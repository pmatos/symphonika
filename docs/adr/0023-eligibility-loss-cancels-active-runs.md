# Eligibility loss cancels active runs and releases the claim

If a running issue stops matching its Project eligibility filters, Symphonika will cancel the active provider process, mark the run cancelled, remove `sym:running` and `sym:claimed`, and preserve workspace and logs. Eligibility labels are the operator's live control surface, so removing `agent-ready` or adding excluded labels such as `blocked` or `needs-human` should stop further autonomous work.

The same claim-release rule applies when label-controlled Continuation Eligibility rejects a delayed retry or Continuation. Once that scheduled callback has been consumed without starting or rescheduling work, no live Issue Reservation remains; retaining `sym:claimed` would misrepresent liveness and cause stale-claim detection to add `sym:stale`. If the Issue becomes eligible again, a later poll creates a fresh Run that safely reuses the deterministic Issue Workspace and Issue Branch while the prior Run's cancellation or success evidence remains durable.

Symphonika does not park this work waiting for eligibility to return. Parking would require a durable pause/resume contract that compatibility-workflow retries and Continuations do not have, and would retain autonomous work after an operator deliberately withdrew an eligibility label. Dependency-gate rejection follows the same rule rather than introducing a dependency-specific cancellation reason; see ADR 0081. Raw-FSM State Advances, waiting rows, and their label-immune retries remain governed by ADR 0046/0047 and are outside this decision.
